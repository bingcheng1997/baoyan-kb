### 三个具体问题

#### ❓ 问题 1：竞品对标名单"漏列 4 家"，内部认知与外部现实脱节
**现状**：README 仅提保研岛/保研人/保研网/保研论坛，但实际 **保研上岸鸭（通知量 3755+）+ 寻鹿（带桌面端）+ 加站（AI 对话）+ 通知网（多维筛选）** 才是 2026 真正在分流的玩家。
**风险**：领导评审时若被问"寻鹿有桌面端，你们有吗？" → 无法回答。
**改进建议**：
- 把本次 5 家新数据回写进 `01_竞品调研/竞品分析.md`，作为 v2.1 竞品对标基线
- 在汇报材料"2.1 5 家竞品扫描"表里把"保研上岸鸭/寻鹿/加站/通知网"补上，**标注每家的"实时追赶项"**（例如"寻鹿：申请工作台 → 我们没有，需 Phase 2 评估"）

#### ❓ 问题 2："纯知识定位"被强化得过头，反而掩盖了"信息库"对外的差异化价值
**现状**：v1.1 把"营销话术/智能体代码/SOP"全部砍掉，"05 算法与定位"改名为"05 定位参考规则"。这在内部是对的（避免边界扩散），但**对外的"差异化承诺"也被一起砍掉了**。
**证据**：index.html 实际渲染时保留了 `智能评估`（侧栏表单）+ `双保险`（右侧栏）+ `24H 截止` + `黑话词典` —— 这是产品形态，不是"纯知识"。
**风险**：
- 内部汇报说"纯知识"，网站却看起来是产品 → **立场分裂**
- 内部研究说"沉淀数据"，但 C 端用户进入看到的是 UI → **认知断层**
**改进建议**：
- 把"内部定位 = 纯知识库"与"对外形态 = 信息聚合站"做 **清晰的 1:1 对应说明**（哪个内部板块对应哪个 UI 模块）
- README 增加一段"对外可见的 11 个页面 ↔ 内部 4 大板块"的对应表，让定位可追溯

#### ❓ 问题 3：差异化叙事被压成"一句话护城河"，缺乏与具体竞品的对位
**现状**：汇报材料 §3.2 "保研+留学双规划（独家）" 是一句话定性，没说明**跟谁比、对手做什么、我们强在哪**。
**改进建议**：
- 改成 **3 句话对位**（例）：
  1. **vs 保研上岸鸭（3755 通知）**：对方做"通知密度"，我们做"通知背后的留学出口解读"
  2. **vs 寻鹿（申请工作台）**：对方做"流程工具"，我们做"双通道战略决策"
  3. **vs 保研人学院（1V1 辅导）**：对方做"咨询变现"，我们做"知识沉淀 + 内部赋能"

### 三个具体问题

#### ❓ 问题 1：演示版被"目标数字"反噬——9 院校撑不起 120 院校的承诺
**现状**：index.html 顶部横幅明确写着 `5 通知 + 9 院校 + 4 案例 + 30 术语 · 计划 129 篇 · 当前 5.4%`。
**风险**：
- 内部领导看 5.4% → "项目太早期"
- 外部 B 端顾问点开 → "才 9 所？还不如保研通知网"
**改进建议**：
- **Phase 1 MVP 门槛定在 "30 通知 + 30 院校 + 10 案例 + 15 政策"**（约 30%），不要一上来就喊 129 篇
- index.html 横幅改为"目标 30+30+10+15 · 当前 5.4%"——小目标大承诺，更可信
- 把 30/30/10/15 作为 Phase 1 必达线，剩下 99 篇作为 Phase 1.5 增值

#### ❓ 问题 2："新东方独家优势"在校准数据上完全空白
**现状**：5 大核心板块里**没有"港澳/中外合办"专题**（Phase 3 才补），但汇报材料 §3.2 把"保研+留学双规划"列为护城河。
**矛盾**：宣称独家优势，但 0 条数据。
**风险**：内部评审被问"你港澳专题有几所院校？" → 无法回答。
**改进建议**：
- 把"港澳 6 所（港大/港中/港科/港城/港理/港教）+ 中外合办 10 所（西浦/宁诺/上纽/昆山杜克/北师港浸大等）"的 **20 条骨架先行生产**（不要求完整 Schema，先有占位）
- 在 index.html "院校数据库"筛选项里把"中外合办"先做出来（HTML 已写死 filter pill 但无数据）

#### ❓ 问题 3：案例库 4 例的"代表性"问题被低估
**现状**：4 例案例（清北复交浙标杆），但学生授权 UGC 在汇报材料 §6 风险表里写"需学生授权"。
**问题**：
- 标杆案例授权难度最高（学生不愿暴露）
- 20% 完成度远低于其他板块——说明 **执行卡点在合规而非产能**
**改进建议**：
- 案例库分两层：**公开案例（脱敏+院校公示）** + **内部案例（顾问 1V1 沉淀）**
- 公开案例走"院校官网录取名单公示"路径（合规清晰）；内部案例走"已签约学生授权"（脱敏程度高）
- 当前 4 例应**只走公开路径**，不要硬拉标杆

## 3️⃣ 商业模式评审 · 5.5/10

### 现状梳理
- **README §核心用户**：C 端学生/家长 + B 端顾问 + 内部研究
- **网站形态**：信息聚合站（11 个页面 / 院校库 / 案例 / 政策 / 黑话 / 百问 / 评估 / 双保险）
- **数据透明**：方法论 / 数据源 / 变更日志 / 法律声明（合规意识到位）

### 三个具体问题

#### ❓ 问题 1："内部信息库"和"对外信息站"是同一个产品吗？
**矛盾点**：
- 汇报材料说"基座级新业务线"，但 index.html 完全是个 C 端信息站
- 5 家竞品**全部是 C 端入口**（连保研通知网都做微信群），新东方"纯内部"等于放弃流量入口
**实质判断**：**这其实是一个"内部基座 + 对外面孔"的双层产品**，但 README 没承认这一点
**改进建议**：
- 在 README 顶部加一段：**"两层结构"**
  - 内部层：知识库本体（Markdown + Schema + 标签体系，供智能体/顾问/研究调用）
  - 对外层：信息聚合站（基于内部层渲染，供 C 端/家长/B 端获客）
- 这样"为什么演示版有 UI"就有了解释，而不是"内部 vs 对外"的认知分裂

#### ❓ 问题 2：目标用户"清单"列了 3 类，但用户旅程没画
**现状**：用户列表 = 学生/家长 + 顾问 + 内部研究。但**用户进入网站后做什么？** 没设计。
**对比**：寻鹿做了"三步开始"（找通知 → 建申请表 → 跟进截止），保研人学院做了"导师评价"专项。
**新东方现状**：首页有"智能评估入口 + 24H 截止 + 快捷入口 + 双保险"——4 个动作，但用户不知道该先点哪个。
**改进建议**：
- 用户旅程分 3 条主线（README 加一段）：
  - **学生主线**：今日截止 → 院校库 → 智能评估 → 案例库
  - **家长主线**：双保险 → 政策 → 院校库（按升学路径排序）
  - **顾问主线**：智能评估 → 案例库 → 政策（备查）
- index.html 顶栏增加"身份切换"（学生/家长/顾问）——不是技术问题，是定位问题

#### ❓ 问题 3：内部顾问的"1V1 咨询时调取定位规则"场景没体现
**现状**：README 把"顾问调取"列为用户场景，但**index.html 没有"顾问工作台"入口**。
**对比**：寻鹿有"申请工作台"、保研人学院有"1V1 辅导"。
**风险**：内部 B 端场景（顾问）这个最有付费意愿的用户反而没有专门入口。
**改进建议**：
- Phase 1.5 增加 `pages/consultant.html`（顾问工作台）：快速查定位规则 + 院校数据 + 推荐话术（脱敏）
- 这是"内部工具 → 内部使用 → 验证价值"的最小循环，比直接对外更可控

## 4️⃣ 护城河评审 · 6.0/10

### "保研+留学双保险"独家性验证

| 检查项 | 判断 | 证据 |
|---|---|---|
| 5 家竞品是否做"保研+留学联动"？ | **❌ 5/5 都不做** | 5 家首页均无留学板块（仅保研加油站底部有"留学服务中心"链接） |
| 是否有竞品在留学联动上有尝试？ | 🟡 间接信号 | 保研通知网"深研派"小红书账号讨论过保研 vs 留学选择；保研人学院做"留学服务中心"入口链接 |
| 新东方真的独家吗？ | ✅ **结构性独家** | 新东方留学业务是新东方**已有**业务（留学+语培+考研+国际课程四大板块之一），竞品无留学业务基础 |
| 独家性是否可被复制？ | ⚠️ **18 个月内可被复制** | 寻鹿/保研人学院若与新航道/启德合作，可形成"留学中介+保研"组合 |

### 三个具体问题

#### ❓ 问题 1：独家优势被"埋"在汇报材料一句话里，没有产品化
**现状**：汇报材料 §3.2 "保研+留学双规划"是 1 句话 + 1 个表格（港澳/中外合办/数据互通）。
**但**：index.html 仅右侧栏有个 🔀 双保险 mini 模块（3 行字 + 一个链接）。
**风险**：内部认为这是护城河，外部用户根本不知道。
**改进建议**：
- 把"双保险"提到顶部导航右侧（在"百问"之后），作为 **6 大功能之一**（不是侧栏小卡）
- 双保险页（dual-path.html）应该做 **3 张对照卡**：① 保研路线图 ② 留学路线图 ③ 双保险决策树
- 写一个**双保险决策模型**：哪些学生适合纯保研 / 哪些适合双保险 / 哪些适合纯留学（10 维度输入）

#### ❓ 问题 2："保研 + 留学双规划"没说清"是给谁的"
**疑问**：双保险的目标用户是**保研边缘生**（GPA 3.5 / 排名 10% / 英语 550）还是**学霸**（清北复交浙冲刺者）？
**判断**：应该是 **保研边缘生 + 中等偏上学霸**——因为：
- 学霸不需要双保险（保研稳了）
- 双非学生保研难 → 双保险价值最高
**现状**：index.html 的"双保险"模块没说目标用户
**改进建议**：
- dual-path.html 顶部加"目标用户画像"：**双非/211 中等生 + 想冲刺港澳/中外合办的 985 学生**
- 写 5 个真实故事案例（脱敏）：双非逆袭港中/西浦上岸路径

#### ❓ 问题 3：护城河是"知识联动"还是"客户联动"？
**两个不同命题**：
- 知识联动：保研的港澳数据 + 留学的港澳数据 → 同一份数据两边用
- 客户联动：保研客户被留学业务覆盖 → 新东方内部跨业务转化

**汇报材料说的"数据互通"是知识联动**，但护城河真价值是**客户联动**（让新东方留学客户同时考虑保研、保研客户同时考虑留学——内部 cross-sell）。
**改进建议**：
- 把护城河重定义为"**新东方内部 cross-sell 能力**"——这是**真正竞品学不来的**
- 数据指标改为：保研知识库触达 → 新东方留学业务咨询数 / 留学业务触达 → 保研业务咨询数
- Phase 3 的应用层必须打通"保研咨询 → 留学咨询"内部路由

## 5️⃣ 内容生产策略评审 · 6.5/10

### 现状策略
汇报材料 §5 写："院校官网优先（对标保研论坛 UGC 参差质量）+ 至少 2 个独立来源 + 学生授权"
但 **实际可执行的策略只有"人工采集"**——AI 生成、UGC 通道在 v2.1 演示版里只是**视觉占位**。

### 三种策略对比

| 策略 | 适合内容 | 当前使用 | 优劣 |
|---|---|---|---|
| **人工采集** | 院校通知、政策、本校政策 | ✅ 主要 | 准确度高 / 产能受限（9 院校 / 5 通知 / 5 政策 = 人工极限附近） |
| **UGC（学生授权/院校公示）** | 案例、经验、面试真题 | ⚠️ 部分（4 例案例） | 真实度高 / 合规风险（脱敏+授权） |
| **AI 生成** | 政策解读、院校概览、档位划分 | ❌ 未启用 | 产能高 / 准确度低（幻觉风险） |
| **外源 QA（多源交叉）** | 数据点校验 | ✅ 工程流程 | 准确度高 / 速度慢 |

### 三个具体问题

#### ❓ 问题 1："院校官网优先"在 MVP 阶段反而是瓶颈
**矛盾**：
- 目标：8 周内 100 通知 + 120 院校
- 现实：每个院校官网通知需人工抓取 → 120 院校 × 5 通知 = 600 条人工抓取
- 单人产能：5-10 条/天 → **60 天完成 600 条 = 12 周**，超出 Phase 1 8 周计划

**改进建议**：
- **MVP 阶段**采用"**聚合站搬运 + 人工核验**"（保研上岸鸭/通知网已有通知 → 我方核验院校官网 → 入库）
- **长期阶段**建立"院校官网 + 聚合站 + UGC"三源交叉，人工只在冲突时介入
- 这是"先有再优"的标准 MVP 路径，不要硬扛人工采集

#### ❓ 问题 2：AI 生成策略"写在汇报里但没启动"
**现状**：汇报材料 §5 提到"复用 v7.1 留学知识库的外源 QA/双层架构"——但**AI 生成在 v2.1 演示版里没出现**。
**风险**：留学知识库（v7.1）已经有 AI 生成经验，保研业务**应该复用而不是从零开始**。
**改进建议**：
- **第 1 周**就把留学 v7.1 的 AI 生成 Prompt 模板复制到保研侧跑通（院校概览/政策解读 5-10 篇）
- AI 生成的内容**标注"AI 辅助生成"**，与人工采集分开标签
- 4 个 schema 增加 `data_source: manual/ai/ugc` 字段

#### ❓ 问题 3：UGC 通道"写在 index.html 但没接通"
**现状**：index.html 底部有 4 个"共建者"卡片（提交通知/授权案例/反馈数据/加入团队），**全部是链接到 contribute.html**——但 contribute.html 大概率是空页。
**风险**：UGC 是空头支票，外部用户提交无门、运营无响应。
**改进建议**：
- Phase 1.5 至少做 **2 个真实 UGC 入口**：
  - "邮件反馈"——24h 回复（已写在 index.html）
  - "学生授权案例"——脱敏模板 + 在线表单
- UGC 提交数据**先人工审核**再入库，不要全自动
- 跑通 1 个月后再评估"在线审核工具"是否值得做

## 6️⃣ KPI 路径与上线运营评审 · 4.5/10

### 现状
- **演示版 KPI**：进度条（5% / 7.5% / 20% / 16.6%）——纯产能指标
- **汇报材料 KPI**：M3 ≥ 9.0 质检合格线 + Phase 1-3 文档数 + 工程化标准
- **没有**：DAU / 通知点击率 / 收藏率 / 用户旅程完成率 / 内部使用率

### 三个具体问题

#### ❓ 问题 1：KPI 全是"供给侧"指标（产出多少），缺"需求侧"指标（用多少）
**现状**：所有数字都是"已生产 XX 篇"。
**缺失**：
- 通知点击率（哪些通知被点最多 → 反映真实需求）
- 院校对比使用率（浮动对比栏触发 → 衡量用户决策深度）
- 24H 截止模块点击率（高紧迫内容接受度）
- 智能评估完成率（C 端用户填表率）
**改进建议**：
- **上线前必接** 4 个埋点（自建 Plausible/Umami 即可，无需 GA 合规）：
  - 通知卡片点击 → 外链（衡量通知价值）
  - 院校对比栏触发（衡量决策深度）
  - 智能评估提交（衡量高意向用户）
  - 黑话词典展开（衡量新手用户）
- **上线后 4 周**回看，决定哪些模块加码、哪些砍掉

#### ❓ 问题 2："内部使用 → 对外开放"两段式 KPI 没区分
**风险**：内部 8 周数据生产完，**直接对外开放**等于赌——如果定位不对外，120 万用户不会来。
**改进建议**：
- **阶段 A（内部使用，4 周）**：仅新东方内部顾问 + 留学顾问 + 内部研究团队可访问
  - KPI：内部周活跃 ≥ 50 人 / 顾问 1V1 调用知识库 ≥ 3 次/天 / 留学顾问 cross-sell 成功率 ≥ 5%
- **阶段 B（限量对外开放，4 周）**：仅限新东方留学/考研在读学员（私域流量）
  - KPI：DAU ≥ 500 / 通知点击率 ≥ 30% / 智能评估提交率 ≥ 5%
- **阶段 C（全量开放，4 周+）**：C 端全开放
  - KPI：DAU ≥ 5000 / 收藏率 ≥ 10% / 跨业务咨询转化 ≥ 3%

#### ❓ 问题 3：竞品上线节奏倒推，Phase 1 8 周时间表偏乐观
**对比**：
- 保研上岸鸭 3755 通知 + 微信群 = 至少 1 年积累
- 寻鹿带桌面端 v0.2.22 = 至少 6 个月开发
- 保研加油站 500 高校 + AI 对话 = 至少 1 年积累

**新东方 Phase 1**：8 周 129 篇 → 平均每周 16 篇 → 每天 2.3 篇文档 → **单人极限**。
**风险**：单点故障（人员请假/离职 → 整个 Phase 1 延期）。
**改进建议**：
- 8 周目标改为 **12 周**（更现实）
- **Phase 1 团队至少 3 人**（内容 1 + 数据工程 1 + QA 1），不是单兵
- 把"129 篇"重新拆：**MVP 核心 50 篇**（8 周可达）+ **扩展 79 篇**（4 周 Phase 1.5）

## 🚨 最紧急 3 项产品策略调整（Top 3）

### 🚨 Top 1 · 必须做 · 7 天内启动

**项目：重新定义 MVP 数据门槛，从"129 篇"压到"50 篇"**

**为什么**：当前 9 院校 / 5 通知 / 4 案例撑不起"120 万保研市场"的承诺。演示版被"目标数字"反噬，外部用户进入即失望。

**做什么**：
1. 重新定义 **MVP 核心 50 篇**：30 通知 + 30 院校（含港澳 6 + 中外合办 5 骨架）+ 10 案例 + 15 政策（仅教育部级 + Top5 985 本校）
2. 8 周计划改为 **MVP 8 周 + 扩展 4 周**（Phase 1.5）
3. 团队从单兵扩到 **3 人**（内容 1 + 数据 1 + QA 1）
4. index.html 横幅改写：`目标 50 篇 · 当前 5.4%`（小目标大承诺）

**预期收益**：演示版可信度↑↑↑ / 内部 KPI 可达性↑↑ / 领导评审风险↓↓

---

### 🚨 Top 2 · 必须做 · 14 天内启动

**项目：把"保研+留学双保险"做成产品化护城河，不是一句话**

**为什么**：5 家竞品 5/5 都不做"保研+留学联动"——这是真独家。但内部认知是"一句话定性"，外部用户根本感知不到，**18 个月内可能被新航道/启德+寻鹿复制**。

**做什么**：
1. dual-path.html 重做（不是 3 行字 mini 模块）：3 张对照卡 + 双保险决策模型 + 5 个真实案例（双非逆袭港澳/中外合办）
2. index.html 顶部导航加"双保险"主入口（不在侧栏）
3. 写一份 **双保险决策 Prompt**（10 维度输入 → 推荐路径），可作为智能评估的"保研 vs 留学 vs 双保险"分支
4. 与新东方留学业务对接：保研咨询 → 留学咨询内部路由（哪怕邮件层面先跑通）

**预期收益**：差异化承诺可感知↑↑↑ / 新东方内部 cross-sell 通道↑↑ / 竞品复制成本↑↑↑

### 🚨 Top 3 · 必须做 · 21 天内启动

**项目：两段式 KPI + 4 个埋点，"内部使用 → 对外开放"分阶段验证**

**为什么**：当前所有 KPI 都是"产出多少"，**没有"用多少"**。Phase 1 8 周做完直接对外，等于赌定位。寻鹿/上岸鸭跑了 1 年才到现在的形态，新东方 8 周就想对标不现实。

**做什么**：
1. **接 4 个埋点**（Plausible 自建 / Umami 开源，无需 GA 合规）：
   - 通知卡片点击 → 外链
   - 院校对比栏触发
   - 智能评估提交
   - 黑话词典展开
2. **阶段 A · 内部使用 4 周**：仅新东方内部（顾问 + 留学 + 考研 + 研究团队），KPI = 周活 ≥ 50 / 顾问日调用 ≥ 3 次 / cross-sell 成功率 ≥ 5%
3. **阶段 B · 限量对外开放 4 周**：仅限新东方在读学员（私域流量），KPI = DAU ≥ 500 / 通知点击率 ≥ 30% / 评估提交率 ≥ 5%
4. **阶段 C · 全量开放**：DAU ≥ 5000 / 收藏率 ≥ 10% / 跨业务转化 ≥ 3%
5. 每个阶段 4 周末做 **1 次评审**：哪些模块加码、哪些砍掉、要不要延期

**预期收益**：上线风险↓↓↓ / 用户真实需求可见 / 内部 ROI 可量化
